# 样本

MiniMax H3（自建池，720p，9:16，6 秒）生成的原始视频，以及在这些底片上用剪辑和局部合成注入错误得到的样本。

| 目录 | 内容 |
|---|---|
| `generated/` | H3 原始输出 15 条（`场景__错误__seed.mp4`）及请求记录（含完整提示词和 seed） |
| `batch2/` | 底片 S03、S05、S07（seed 20261120），40 条视频，清单见 [`videos/INDEX.md`](batch2/videos/INDEX.md) |
| `batch3/` | 底片 S04（seed 20261119）、S01、S06（seed 20261121），31 条视频，清单见 [`videos/INDEX.md`](batch3/videos/INDEX.md) |
| `showcase/` | 展示页和压缩后的预览视频 |

## 文件名

`底片__类型__错误编号__子类.mp4`，例如 `S05-h3b__multi__S05.I9+S05.I2+S05.I8__PF4+PF8+PF5.mp4`：S05 的 h3b 底片上同时有 3 个产品事实类错误（Logo 反字、字幕功率错、光环不亮）。类型：`clean` 正确、`decoy` 干扰项、`control` 对照、`single` 单错误、`multi` 同类多错误、`combo` 异类多错误。干扰项的后缀是 `looks-<看起来像的类别>`。每批的 `videos/INDEX.md` 逐条列出错误的时间窗口和描述。

**盲审时不要直接用 `videos/`**，文件名里有答案。运行 `node src/cli.mjs sheets --out samples/batch2`，会把视频按不透明的 `blind_id` 复制到 `annotation/blind/`，只把那个目录给标注员。

## 同一镜头多错误

两种做法，都不是把几段画面拼起来：

1. **局部合成**（确定性，真值精确）：时间轴不动，只改画面里的一块区域，多个错误叠加在同一段连续画面里。用到的操作：按颜色选区换色（`tint` + `key`）、区域定格（`freeze_region`，例如水一直倒、玻璃杯却始终是空的）、区域复制（`clone`，例如盒里多出第三只耳机）、区域镜像（`flip_region`，例如 Logo 变反字），再加上字幕、静音、白闪。共 13 条，在 INDEX.md 里标为「同一连续镜头」。场景里的 `bundles` 定义了专门设计的 3 错误组合。
2. **提示词同时要求多个错误**（模型生成，需复核）：只有文字类错误能稳定做出来。

| 视频 | 要求的错误 | 结论 |
|---|---|---|
| `generated/S01__S01.I6+S01.I8__seed20261121` | Logo 写成 LUM0 + 杯身伪文字 | 两处都出现：Logo 变成竖排并多出一个「0」；杯底一行读不通的小字（细微） |
| `generated/S08__S08.I5+S08.I8__seed20261121` | 罐身乱码 + 盖面写成 AUAR | 罐身乱码出现（细微）；盖面仍近似 AURA，未做出 |
